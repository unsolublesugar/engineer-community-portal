# 開発ルール

## コーディング規約
- Python 3.9+ 互換のコードを書く
- 型ヒントを活用する
- docstring は Google スタイルで記述する

## Git ワークフロー

### ブランチ運用
- 修正・機能追加時は以下の流れで作業する:
  1. GitHub Issue を作成して作業内容を記録
  2. `main` から作業ブランチを切る
  3. ブランチ名は `feature/<概要>`、`fix/<概要>`、`docs/<概要>` 等のプレフィックス付き
  4. 作業ブランチで実装・コミット
  5. Pull Request を作成（関連 Issue をリンク）
  6. レビュー・確認後に `main` へマージ
- ただしユーザーから明示的に指示があった場合は `main` への直接プッシュも可

### Pull Request 作成時の付与情報
- **Assignee**: リポジトリオーナー（作業者）をアサインする
- **Label**: PR の内容に応じて以下から付与する
  - `enhancement`: 新機能追加
  - `bug`: 不具合修正
  - `documentation`: ドキュメント・README・CHANGELOG 等の更新
  - `question`: 仕様や方針の相談
  - その他必要に応じてリポジトリ既存ラベルを利用

### コミット
- コミットメッセージは日本語 OK
- 機能単位で小さくコミットする

## テンプレート
- Jinja2 テンプレートは `src/templates/` に配置
- テンプレート内のコメントは HTML コメント形式で

## データ管理
- イベントデータは `data/events/NNN.yaml` 形式
- NNN はゼロ埋め3桁のイベント番号（例: 001, 076）
- YAML の文字コードは UTF-8

### イベント YAML の `talks` ルール
- **前座・MC・オープニング・運営紹介などの非LT枠は `talks` に含めない**（厳守）
  - `talks` は本編 LT（登壇発表）のみを記載する
  - 前座枠が告知されていても YAML には書かない
- 開催前で登壇者未定の枠は `name: TBD` / `id: tbd` で TBD 枠として記載する
- 開催後は YouTube 概要欄等のタイムスタンプを基準に確定情報へ差し替える
